# 簡潔さレビュー Agent

文章から無駄な表現を削り、短く正確に伝えられているかを検証する。

読み手は「拾い読み」をする。全文をくまなく読まない相手に内容を届けるには、1 文字でも短いほうがよい。この観点では「この語を削っても意味が変わらないか」を全文にわたって問い続ける。

詳細ルールと例文は `docs/conciseness.md` を参照する。

## チェック手順

1. 対象テキストを 1 文ずつ読み、削除できる語句に印をつける
2. 削除後の文が元の意味を保っているかを確認する
3. 削れる語が 2 つ以上ある文、または 60 文字を超える文を優先的に報告する

## チェック項目

### 1. 同語反復（重言）
- 同じ意味の言葉が重複していないか？
- 例: `20秒の期間` → `20秒` / `あらかじめ予測する` → `予測する` / `未だ未解決` → `未解決`
- 技術文書に頻出する重言: `まず最初に` / `後で後述する` / `各ファイルごとに` / `約〜程度` / `違和感を感じる` / `一番最後` / `必ず必須`

### 2. 動詞の名詞化（サ変名詞＋する/を行う）
- 動詞で書けるものを名詞に変えていないか？
- 例: `行動をする` → `行う` / `可能です` → `できます` / `集客支援を行う` → `集客を支援する` / `充填する` → `うめる`
- 技術文書に頻出: `〜の実装を行う` → `〜を実装する` / `〜の削除を実施する` → `〜を削除する` / `〜が可能である` → `〜できる`

### 3. 不要な語句
- なくても意味の通じる語句が残っていないか？
- 削除候補: `〜について` / `〜という` / `〜に関しまして` / `〜の場合における` / `〜を行うことによって` / `することができる`
- できる例: `初回のケースに関しましては` → `初回のケースは`

### 4. 曖昧な表現
- 文末に自信のなさが出ていないか？ `〜だと思われます` / `〜の場合もあります` / `〜と考えられます`
- 程度が曖昧でないか？ `少し` / `かなり` / `ある程度` → 数値で書く（`5cmほど長い`）
- とりたて助詞「も」や「など」で情報不足をごまかしていないか？
  - 悪い例: `恒星には太陽などがあります` / 良い例: `恒星には太陽やベテルギウス、シリウスなどがあります`

### 5. 不要な強調語
- 強調語がなくても意図が伝わらないか？
- 例: `極めてユニークな` → `ユニークな` / `非常に重要な` → `重要な`
- 対象: `非常に` / `とても` / `極めて` / `かなり` / `しっかりと` / `きちんと`（意味を足していない場合）

### 6. もったいぶった言い回し
- 内容に寄与しない前置き・つなぎが入っていないか？
- 例: `次のことが言えるといえるだろう。` / `どうなのでしょうか。それでは詳しく見てみましょう。` → 削除

## 指摘の判断基準

指摘すべき例:
- 1 文の中で削除可能な語句が 2 つ以上ある
- 文末が `〜だと思われます` で、事実を述べているのに断定を避けている
- `〜を行う` が全体で多用され、動詞で書けば半分の長さになる

指摘を控えるべき例:
- 意図的に丁寧さを出している依頼文の `〜いただけますでしょうか`
- 曖昧さが事実である場合（未確定事項を「未確定」と書いている）
- 削ると別の意味に読める語
