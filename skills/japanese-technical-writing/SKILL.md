# 日本語テクニカルライティングガイド

欧米標準のテクニカルライティング技術、内閣通知『公用文作成の要領』、文部科学省『くぎり符号の使ひ方』、
新聞社・出版社の規準を典拠とするルール集。

読み手は情報を得るために「拾い読み」をする。全文を読まない相手に内容を届けるため、
簡潔で誤解のない文章を書く。

## 2つのモード

| モード | 使う場面 | やること |
|---|---|---|
| **執筆モード** | 自分が文章を出力するとき（PR説明、コミットメッセージ、ドキュメント作成、要約など） | 下の「執筆ルール」に従って書き、出力前にセルフチェックを行う |
| **レビューモード** | 既存文章のレビュー・改善を依頼されたとき、または300行以上の長文を新規作成したとき | `agents/` の7観点を**並列subagent**で網羅的にチェックする |

判断に迷う場合は執筆モードを使う。短いテキスト（コミットメッセージ、1〜2 段落の説明文）に
subagent を起動してはいけない。

このファイルには執筆時に頻繁に引くルールだけを置く。
約物の詳細、副詞の呼応、引用の作法などレビュー時にしか判定しないルールは `agents/` にある。
根拠と原典の解説は `docs/` にある。

# 執筆モード

## 基本原則

1. **簡潔に書く**: 無駄な表現を省き、短く明確に伝える
2. **能動態を使う**: 原則として能動態で書き、文章に力強さと明確さを持たせる
3. **文体を統一する**: ですます調/である調を混ぜない。文末表現の繰り返しを避ける
4. **主語と述語を近くに置く**: 主語と述語の間に余計な語句を入れすぎない
5. **やさしい言葉を使う**: 難しい漢字、専門用語、カタカナ用語を避ける

## 出力前セルフチェック

- [ ] 削れる語句はないか（`〜について`、`〜という`、`〜を行う`、不要な強調語）
- [ ] 文末が 3 回以上連続していないか
- [ ] ですます調/である調が混在していないか
- [ ] 主語と述語が離れすぎている文はないか
- [ ] 理由なく受動態を使っていないか
- [ ] 指示語（それ、これ、その）の指すものが一意に決まるか
- [ ] 箇条書きの各項目の文法構造がそろっているか
- [ ] 形式名詞・補助動詞がひらかれているか（`〜する事` → `〜すること`）
- [ ] `・・・` や `！` を使っていないか

## 執筆ルール

### 簡潔さ

- **同語反復を避ける**: 20 秒の期間 → 20 秒 / あらかじめ予測する → 予測する / 未だ未解決 → 未解決 / まず最初に → まず / 各ファイルごとに → ファイルごとに
- **動詞の名詞化を避ける**: 行動をする → 行う / 可能です → できます / 実装を行う → 実装する / 削除を実施する → 削除する
- **不要な語句を省く**: 初回のケースに関しましては → 初回のケースは。`〜について` `〜という` `することができる` は多くの場合削除できる
- **曖昧な表現を避ける**: 効果的だと思われます → 効果的です / 少し長い → 5cm ほど長い。`も` `など` で情報不足をごまかさない
- **不要な強調語を削除する**: 極めてユニークな → ユニークな / 非常に重要な → 重要な
- **もったいぶった言い回しを避ける**:「次のことが言えるといえるだろう」「それでは詳しく見てみましょう」→ 削除

### 文構造

- **主語と述語を近くに置く**: 長い修飾句が挟まる場合は文を分割する
    - 悪い例: 弊社は、ユーザー様がご満足される視聴者向けマーケティング施策を、弊社サービス会員や関係者に、弊社の商品の根強いファンになっていただくことを期待し展開しております。
    - 良い例: 弊社は、さまざまな視聴者向けマーケティング施策を展開しております。その目的は、弊社サービス会員や関係者にご満足いただき、弊社商品の根強いファンになっていただくことです。
- **主語を統一する**: 連続する文で、文脈上の主語と文法上の主語を一致させる
- **能動態を原則にする**: 受動態は「動作主が重要でない」「動作の対象を強調する」「あえて主張を弱める」「能動態が連続して単調になる」場合にだけ使う
- **修飾語を被修飾語の近くに置く**: 素早い花の先に止まったテントウ虫 → 花の先に止まった素早いテントウ虫
- **並列する要素は文法構成をそろえる**: デザイン性と機能が優れていること → デザイン性と機能性。箇条書きも同じ
- **比較の対象を書く**: もっとも速いやり方です → 今まで試した中でもっとも速いやり方です

### 文体

**文末を統一する**:「ですます調（敬体）」か「だである調（常態）」のいずれかに統一する。

**文末の繰り返しを避ける**: 同じ文末を 3 回以上続けない。
`〜です` / `〜ます` / `〜でした` / `〜ません` / `〜でしょう` / `〜ください` / 体言止めを混ぜる。

**話し言葉を書き言葉にする**

| 話し言葉 | 書き言葉 | 話し言葉 | 書き言葉 |
|---|---|---|---|
| いっぱい | 多い | ですから | そのため |
| ちょっと | 少し | たぶん | おそらく |
| とても | 非常に | 一番 | 最も |
| そういう | そのような | いつも | 常に |
| もっと | さらに | ちゃんと | きちんと |
| やっぱり | やはり | 絶対に | 必ず |
| けど | が | だんだん | 次第に |
| やっと | ようやく | なので（文頭） | そのため |
| 〜とか | 〜など | 〜みたいな | 〜のような |

**文語体を口語体にする**

| 文語体 | 口語体 | 文語体 | 口語体 |
|---|---|---|---|
| のみならず | だけでなく | すべく | するため |
| においては | では | できぬ | できない |

### 語の選び方

- **やさしい言葉を使う**: 措置 → 処置・取扱い / コンセンサス → 合意 / RFP → 提案依頼書（初出時に説明を添える）
- **不要な省略を避ける**: MTG → ミーティング / MGR → マネージャー。チーム内で定着した略語（API, CI, PR）はそのままでよい
- **独自の複合名詞を避ける**: 時間短縮料理術 → 時間が短縮できる料理術
- **指示語の曖昧さを避ける**:「それ」「これ」が一意に決まらない場合は、名詞を再び書くか「そのカード」のように名詞を補足する

### 漢字・ひらがな

常用漢字表（2136 字）の範囲で書く。常用漢字でも、本来の意味を失った語はひらがなで書く（ひらく）。

| 種類 | ひらく例 |
|---|---|
| 形式名詞 | 〜する事 → 〜すること / 〜する為 → 〜するため / 〜する物 → 〜するもの / その時 → そのとき / 見た所 → 見たところ |
| 補助動詞・補助形容詞 | 〜して下さい → 〜してください / 〜して欲しい → 〜してほしい / 調べて見る → 調べてみる / 行きたく無い → 行きたくない / 〜し易い → 〜しやすい |
| 接続詞 | 但し → ただし / 又は → または / 及び → および / 従って → したがって / 例えば → たとえば |
| 副詞（訓読み） | 既に → すでに / 全て → すべて / 殆ど → ほとんど / 是非 → ぜひ |
| 連体詞・代名詞 | この、その、わが、あらゆる、あなた、われわれ、ここ、そこ |

本来の意味で使う語（時間の「時」、場所の「所」、視覚の「見る」）と固有名詞・専門用語は漢字のまま書く（とじる）。
同じ語が漢字とひらがなで混在しないよう、文書内で統一する。

### 約物

- `・・・` は使わない → `……`（三点リーダー2 つ）
- `！` は公式な文章では使わない。強調は読点・カギ括弧・丸括弧で行う
- 数値は半角アラビア数字。訓読み（1 つ）、順序（1 番目）、副詞（第一に）は漢字
- 括弧は全角に統一する。使いすぎに注意し、本文に入れ込めないか検討する
- 波ダッシュは数値と数値、名詞と名詞をつなぐ: 当日〜3 日 → 1〜3 日
- 読点は誤読を避けるために打ち、打ちすぎない: ここではきものを脱いでください → ここで、はきものを脱いでください

# レビューモード

## Step 1: 対象の特定

1. レビュー対象のファイル・差分・テキストを特定する
2. 文書の種別（README、設計書、手順書、PR 説明文など）と想定読者を把握する
3. 文書全体を読み、支配的な文体（ですます調/である調）を判定する

```bash
# 差分の日本語ドキュメントを対象にする場合
git diff <base-branch>...HEAD --stat -- '*.md'
git diff <base-branch>...HEAD -- '*.md'
```

## Step 2: 並列レビューの実行

以下の 7 観点について、それぞれ専門の subagent を**並列で**起動する。

| 観点 | Agent指示ファイル | 目的 |
|---|---|---|
| 簡潔さ | `agents/conciseness.md` | 同語反復、動詞の名詞化、不要語句、曖昧表現 |
| 文構造 | `agents/sentence-structure.md` | 主語述語、能動態/受動態、並列、比較、修飾語 |
| 語選び | `agents/word-choice.md` | 名詞、指示語、形容詞、副詞の係り受け、助詞 |
| 文体 | `agents/writing-style.md` | 文末統一、繰り返し、話し言葉、文語体 |
| 漢字・ひらがな | `agents/kanji-hiragana.md` | 常用漢字、ひらく/とじるの統一 |
| 約物 | `agents/punctuation.md` | 句読点、括弧、ダッシュ、数値、強調記号 |
| 引用 | `agents/citation.md` | 引用の分量、出典の明示 |

subagent 起動時、各 agent に以下の情報を含めること。

- レビュー対象のファイルパス（または本文全体）
- 文書の種別と想定読者
- 文書全体で支配的な文体
- このスキルのパス（agent 指示ファイルと `docs/` の参照に必要）

subagent 起動のプロンプト例:

```
以下の日本語ドキュメントを「{観点名}」の観点からレビューしてください。

まず {スキルパス}/agents/{観点}.md を読み、レビュー指示に従ってください。
判断に迷う場合は {スキルパス}/docs/ の該当ファイルで詳細ルールと出典を確認してください。

## レビュー対象
- ファイル: {ファイルパス}
- 文書種別: {README / 設計書 / 手順書 / PR説明文 など}
- 想定読者: {読者}
- 支配的な文体: {ですます調 / である調}

指摘には必ず原文の抜粋と修正後の文をセットで含めてください。
コードブロック、コマンド、URL、識別子の中は対象外です。
確信度の高い指摘のみ報告してください。
```

## Step 3: 結果のマージと出力

1. **重複排除**: 複数の subagent が同じ箇所を指摘している場合は統合する。1 箇所に複数の問題がある場合は最も重要なものを主として、残りを補足に回す
2. **重要度順に並べ替え**: 下の順序で整理する
3. **修正案の統合**: 同一箇所への複数の修正案が競合する場合、すべてを反映した 1 つの文を作る

### 重要度の順序

1. **意味が正しく伝わらない問題** — 主語述語の破綻、指示語の曖昧さ、比較対象の欠落、係り受けの崩れ
2. **読みにくさ** — 冗長表現、主語述語の距離、受動態の多用、並列構造の不一致
3. **表記の不統一** — 文体の混在、ひらく/とじるの揺れ、約物の不統一
4. **表記の細部** — 個別の漢字ひらがな、読点の位置

### ラベル

| ラベル | 用途 |
|---|---|
| **must** | 修正必須。意味が誤って伝わる、または明確なルール違反 |
| **should** | 修正推奨。読みやすさが明確に改善する |
| **nits** | 些末な指摘。対応は任意 |
| **suggestion** | 改善提案。より良い表現の提示 |

### 出力フォーマット

````markdown
## 日本語レビュー

対象: [ファイル名]
レビュー観点: 簡潔さ / 文構造 / 語選び / 文体 / 漢字ひらがな / 約物 / 引用

### 総評

[文章全体に対する1-2文の評価。文体の統一状況と、最も多い問題の傾向を書く]

### 指摘事項

#### [must] 主語と述語の距離が遠く意味を取りにくい
- 観点: 文構造
- 箇所: `docs/design.md:42`
- 原文: 本システムは、複数のマイクロサービスから送信されるイベントを、可用性を担保しつつ順序を保証した状態で処理します。
- 修正案: 本システムは、複数のマイクロサービスから送信されるイベントを処理します。処理の際は可用性を担保し、順序を保証します。
- 理由: 主語「本システムは」と述語「処理します」の間に40文字以上が挟まっている。文を分割して距離を近づける

#### [should] 動詞の名詞化により冗長
- 観点: 簡潔さ
- 箇所: `docs/design.md:58`
- 原文: バッチ処理の実行を行う
- 修正案: バッチ処理を実行する
- 理由: 「実行を行う」は動詞を名詞化した冗長表現

### 表記の統一（一括修正候補）

| 現在 | 修正後 | 出現数 | 観点 |
|---|---|---|---|
| 〜する事 | 〜すること | 12 | 漢字ひらがな |
| 〜して下さい | 〜してください | 8 | 漢字ひらがな |
````
